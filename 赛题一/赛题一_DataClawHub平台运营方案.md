# DataClawHub 平台宣传运营方案（落地版）

> 数联科技 × 华东师范大学 AI 智能体校园黑客松 · 赛题一
>
> 本方案只设计「怎么宣传、怎么落地」：不预设未知的人数、金额与日期，所有动作按「准备 → 试水 → 放量 → 收口」推进，以初赛提交日为终点**倒排**。评分要求的目标画像、内容策略、渠道、排期、投入产出、风险预案、平台改造均已覆盖。

---

## 0. 一页纸看完

- **运营主张**：给你的 Agent 找第一份活。
- **做法一句话**：把赛题二作品打包成 DataClawHub「制品」当钩子（注册后才能 fork）→ 通过免费渠道按固定节奏发内容 → 用一张表记录转化、按周调整。
- **考核重点**：不只看注册数，看注册后有没有真实动作——发布制品、认领任务、fork、互动、转发。
- **为什么可行**：内容全部复用赛题二成果，不额外生产；渠道全免费；按队员特长轮值，每天只需几分钟记录；即使最终流量一般，「平台制品 + 真实后台截图 + 复盘记录」仍然成立，方案交得出。

## 1. 平台理解与目标人群

### 1.1 三条事实（决定怎么宣传）

| 事实 | 宣传时怎么说 |
| --- | --- |
| 平台以「任务」为单元，智能体可以自主接单、系统自动评分 | 「这里有真实的活，不是玩具 Demo」 |
| 形成「发布任务—接单交付—自动评分—作品公开沉淀」的闭环 | 「你的 Agent 能接真实任务并留下公开作品，不是一次性作业」 |
| 赛事由数联科技 × 华东师范大学联合举办、阿里云冠名，赛题来自物流 / 可信数据空间真实行业问题（见官方赛事 PDF 第 1、3 页） | 「场景真实、有官方背书，毕设竞赛能用」 |

**一句话定位**：不是数据下载站，是 Agent 的任务市场。

### 1.2 两类人群（主攻一类，兼顾一类，不撒胡椒面）

| | 主攻人群 | 兼顾人群 |
| --- | --- | --- |
| 是谁 | 会写代码 / 搭 Agent 的同学、技术社团成员、研究生 | 要数据做毕设竞赛的同学、找实习的同学 |
| 动机 | 给 Agent 找真实场景，接单、交付、通过系统评分 | 拿正规数据、攒公开作品 |
| 卖点 | 你的 Agent 能接真实的活，不是玩具 Demo | 真实行业场景数据集 + 作品公开展示曝光 |
| 渠道 | 掘金或知乎（选一个）、技术社团群、B 站 | 学院群、导师、朋友圈、小红书 |

**判断依据**：报名结束后校内泛流量已过峰，技术人群自带动机、转化率最高；兼顾人群只在顺手渠道覆盖，不专门投入。

## 2. 转化漏斗与记录方式

### 2.1 我们关心的五级漏斗（只定义口径，不预设数字）

| 环节 | 怎么算 | 数据从哪看 |
| --- | --- | --- |
| 曝光 | 各平台阅读 / 播放量 | 平台后台 |
| 点击 | 点进落地页 / 引流链接 | 分渠道短链或落地页 |
| 注册 | 填写队伍邀请码的新注册用户 | 组委会邀请码后台 |
| 激活 | 注册 7 天内完成发布 / 认领 / fork / 互动 | 平台前台可见行为 |
| 转发 | 通过制品页「一键转发」产生的分享 | 制品页 / 平台统计 |

**归因口径（与组委会规则一致，必须照此统计）**：每位用户以其**首次进入的队伍专属邀请链接 / 邀请码**作为唯一归属；同一用户后续重复访问、再次点击链接，**不重复归因**。因此各渠道要使用可区分的专属链接，并把力气放在"第一次触达就讲清价值"，而不是反复刷同一批人的点击。

**目标怎么定**：不拍脑袋设指标。准备期先确认后台能看到哪些口径；试水期跑出真实基线；再据此确定放量期的努力目标。复盘时目标与实际照实对比，偏差和原因也照实写——**承认偏差不扣分，材料缺失才扣分**。

### 2.2 一张飞书表，每天一行

字段：日期 ｜ 渠道 ｜ 内容链接 ｜ 曝光 ｜ 当日新增注册 ｜ 备注（限流 / 改版等异常）。

每天固定时间由轮值同学填一行。**备注列最重要**，没有它，数据涨跌事后无法解释。

## 3. 就做三件事

### 第一件：做钩子（准备期完成）

1. 把赛题二的**数据集、Prompt、可运行 Demo** 打包上架为 DataClawHub 制品，写明「注册后方可 fork」。
2. 做一个简单落地页（GitHub Pages 免费托管，单页即可）或一张带二维码的海报：首屏直接放「一个可立刻认领的真实任务 + 领取按钮」，不写「欢迎了解」类空话。
3. 全队自己先走一遍「看到内容 → 点链接 → 注册填邀请码 → fork 制品」，不卡才算过。

### 第二件：发内容（固定「3+1」节奏）

- **每周 3 条小红书图文**：上手教程、比赛收获、Agent 接单演示。
- **每周 1 篇技术实操文**：掘金或知乎选一个发，标题只说一件具体的事，如《零代码 10 分钟，让一个会接单的 Agent 上线》。
- **1 条 60 秒演示视频多处复用**：B 站、视频号、朋友圈、小红书，一次录制不重复劳动。
- **全队朋友圈定期转发**；学院群 / 导师渠道在放量期集中推送。
- **赛题二核心成果一旦跑通，立刻安排首发**（如《让 AI 查数不再编数字：37 道业务题从全部答错到 37 题全对》，具体数字以赛题二实测为准、不夸大），当天全员转发，作为赛期最大一波。

内容 SOP（三条就够）：
1. 每篇必须有：作品截图 / 视频 + 邀请码或落地页链接；
2. 小红书正文**不放外链**（会限流），统一评论区置顶引导；
3. 所有内容发布前由一人过目，数据和事实不许瞎写。

**明确不做**：不投信息流广告、不买粉、不做现金抽奖——这类注册在邀请码口径下是无效增长，还可能违规。

### 第三件：看数据做调整

每周固定一次 30 分钟周会：看哪条内容、哪个渠道带注册最多，下周砍掉无效的、加码有效的。收口期只保留转化最好的两个渠道。

## 4. 渠道与分工

| 渠道 | 发什么 | 频次 |
| --- | --- | --- |
| 朋友圈 / 微信群 | 海报 + 一句话文案 | 全队定期转发 |
| 小红书 | 图文（教程 / 收获 / 演示，正文零外链，评论区引导） | 3 条 / 周 |
| 掘金或知乎（二选一） | 技术实操长文 | 1 篇 / 周 |
| B 站 / 视频号 | 60 秒演示视频（一次录制，多平台复用） | 每周有更新 |
| 学院群 / 导师 / 课程群 | 海报 + 赛事说明 | 放量期集中推 |

**分工方式**：赛前按队员特长认领渠道、排出轮值表；另指定一人负责所有内容发布前过目。每天的数据记录按周轮值，不固定占用某一个人。

**零成本资源**：API 与算力优先使用平台 / 赛事提供的免费额度，不足部分用队员自有资源，不额外采购；线下摊位、场地找学院团委 / 社团借用；数联开放日的照片和见闻是第一批现成素材。

## 5. 阶段排期（以初赛提交日倒排）

| 阶段 | 主要动作 | 完成标志 |
| --- | --- | --- |
| **准备期** | ① 向组委会确认：邀请码何时上线、能否看到渠道来源、转发能否统计<br>② 注册各平台账号、建好飞书记录表<br>③ 赛题二制品上架，全队自测「看到 → 注册填码 → fork」全链路<br>④ 海报 + 落地页完成 | 自己点一遍链路无卡点 |
| **试水期（约一周）** | 小批量发布小红书、实操文、视频各若干；每天记数据，找出带量的内容类型和渠道 | 真实基线数据入表，确定放量期目标 |
| **放量期（约一周）** | 按「3+1」节奏持续发布；赛题二成果跑通即首发、全员转发；学院群 / 导师集中推送；每周淘汰无效渠道 | 有效渠道稳定带来注册 |
| **收口期（提交前数天）** | 只留转化最好的 2 个渠道；各平台后台与邀请码后台截图归档；完成复盘；按时提交 | 材料齐全、成功提交 |

**节奏原则**：内容全部复用赛题二材料，不另起炉灶；运营与赛题二冲突时，一律先保赛题二核心实现跑通，再安排成果首发与放量。

## 6. 投入成本与产出

| 项目 | 处理方式 |
| --- | --- |
| 海报 / 打印物料 | 小额现金，按需印制，不提前囤 |
| 易拉宝 | 优先向学院 / 社团借用，不足再买 |
| 换量小周边 | 只准备少量，用于社团互推、线下交换 |
| 落地页 / 域名 | GitHub Pages 免费托管，零现金 |
| API / 算力 | 优先用平台 / 赛事免费额度，不足用队员自有资源，不额外采购 |
| 线下场地 | 学院团委 / 学生社团借用 |

**现金原则**：除小额物料外几乎零现金，以资源置换为主；具体花费按队费与赞助情况决定，不预设预算数字。

**四项产出**：

1. **真实流量证据**：各平台后台 + 邀请码后台截图，按周归档；
2. **平台制品**：赛题二数据集制品（注册后方可 fork）+ 本方案沉淀的运营 SOP（可被他人复用）；
3. **数据记录与复盘**：飞书表导出 + 一页复盘（目标 vs 实际、有效 / 无效动作、下一轮想法）；
4. **平台功能建议**：准备期走查后形成的真实建议清单（见 §8）。

**保底逻辑**：即使流量数字一般，制品、截图、复盘照样成立，不依赖赌单一数字。

## 7. 风险预案（只列最可能遇到的 3 条）

| # | 风险 | 应对 |
| --- | --- | --- |
| R1 | 邀请码上线晚 / 后台看不到渠道来源 | 各渠道用不同短链或落地页分链接区分；落地页加「从哪知道我们」单选项兜底；准备期第一时间向组委会确认 |
| R2 | 小红书对导流内容限流 | 正文零外链，只走评论区与主页；被限就把内容转到 B 站和公众号承接，不硬刚 |
| R3 | 全队被赛题二挤占、内容断更 | 只发能复用赛题二的内容，提前存少量备发内容；实在忙不过来就只保朋友圈 + 技术社区两条主渠道 |

## 8. 平台功能改造与使用习惯建议

平台功能改造并非赛题一的最低交付物，我们**主动附加**这一部分以争取加分。准备期全队完成一次「注册 → 发布制品」完整走查，用真实体验填写；初步判断如下，正式提交前用走查发现替换：

| # | 模块 | 不习惯的地方（走查后填实） | 建议 | 优先级 |
| --- | --- | --- | --- | --- |
| 1 | 注册登录 | 【走查后填】初步：步骤多、缺第三方登录 | 支持 GitHub / 微信一键登录；邀请链接点开自动带邀请码，免手填 | P0 |
| 2 | 新手引导 | 【走查后填】初步：注册后不知道先干什么 | 注册后立刻给一个几分钟能完成的示例任务 + Agent 模板 | P1 |
| 3 | 制品转发 | 【走查后填】初步：转发入口不明显、统计不到 | 制品页加「一键转发朋友圈」，并能按队伍维度统计 | P1 |

填写纪律：没有问题的模块写「无显著不符」及理由，不占位、不硬凑。

## 11. 路演三段式（≤5 分钟视频或现场演示脚本骨架）

严格按组委会要求的顺序讲，每段控制时长，"带来了什么"只用第 10 节的真实数字：

1. **做了什么（约 1.5 分钟）**：把赛题二成果做成 DataClawHub 制品（注册后可 fork）；建落地页 / 海报；按"3+1"节奏在 N 个渠道发了 N 条内容；现场演示一次「专属链接 → 注册填邀请码 → fork 制品」。
2. **带来了什么（约 2 分钟）**：专属链接访问 __、邀请码注册 __、7 日激活 __、制品 fork / 互动 __（数字取自 §10.2，不填未发生的数）；最有效的渠道 / 内容各是什么，用截图佐证。
3. **下一步怎么放大（约 1 分钟）**：加码已验证的 2 个渠道、把跑通的运营 SOP 交给更多队伍复用、按 §8 清单推动平台改进。

> 若提交时执行期数据尚不完整：如实展示已完成的真实动作与现有基线，明确说明哪些指标在统一实测期继续验证，不用预估数冒充结果。
