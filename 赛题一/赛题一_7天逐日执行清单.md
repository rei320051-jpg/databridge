# 赛题一 · 7 天逐日执行清单（2026-10-08 → 10-14）

> 配套文件：《赛题一_DataClawHub平台运营方案.md》。本清单把方案压成提交日前的 7 个可执行日，**每一天都有"当天必须产出的可核验证据"**，直接对应官方四类交付物：运营方案 / 执行材料 / 数据复盘 / 路演展示。
>
> 铁律（每天开工前默念）：
> 1. **不编数**：没有真实发生的指标留空并说明，绝不事后补造；
> 2. **首入口归因**：一个用户只算在其首次进入的队伍专属邀请入口上，重复访问不重复归因；
> 3. **发布前一人过目**：所有对外内容当天由固定审核人确认事实后再发；
> 4. **先保赛题二**：10-08 赛题二功能冻结，之后只修 bug；运营动作与赛题二冲突时让位于赛题二；
> 5. **小红书正文零外链**，统一评论区 / 主页引导。
>
> 角色（请在 D1 把名字填实）：
> - 审核人（固定 1 人，建议 成员3）：__；台账轮值：成员1 / 成员2 / 成员3 按周轮；
> - 制品与落地页：__；技术社区长文：__；小红书 / 短视频：__；学院群 / 导师渠道：__。

## D1 · 10-08（四）准备期：把"能跑通的一切"先跑通

> 与赛题二冻结同日，运营动作安排为"轻执行、重搭建"，不占用核心开发时间。

- [ ] **向组委会 / 平台确认 4 件事**（拿不到答案就启用括号内兜底）：
  - [ ] 队伍专属邀请码 / 邀请链接何时、从哪领取（未上线 → 用分渠道落地页 +「从哪知道我们」单选项兜底，对应风险 R1）；
  - [ ] 后台能否看到：访问、注册、激活、按队伍归因；能看到哪些时间粒度；
  - [ ] 制品「注册后可 fork」开关与统计是否可用；
  - [ ] 转发 / 分享能否被平台统计。
- [ ] 注册 / 登记各对外账号：小红书、掘金或知乎（二选一）、B 站、视频号；统一头像、昵称、简介（挂队伍与 DataClawHub）。
- [ ] 按方案 §2.2、§10.1 建好**飞书台账空表**（日期/渠道/内容链接/曝光/点击/注册/7日激活/备注），并建好 §10.2 复盘表空表。
- [ ] **赛题二制品上架** DataClawHub：数据集 + Prompt + 可运行 Demo（用赛题二提交包内容），写明"注册后方可 fork"。
- [ ] 落地页（GitHub Pages 单页）或带二维码海报：首屏 = "一个可立刻认领的真实任务 + 领取按钮"，放专属邀请入口。
- [ ] **全队走一遍全链路并录屏 / 截图**：看到内容 → 点链接 → 注册填邀请码 → fork 制品；任一卡点当天修掉（这是路演第一段的演示素材）。
- [ ] 完成一次平台「注册 → 发布制品」走查，按方案 §8 用**真实体验**替换 3 条建议里的【走查后填】；没问题的模块写"无显著不符 + 理由"。
- [ ] 排好 7 天轮值表与每日固定填表时间。

**当日证据**：账号清单、台账 / 复盘空表链接、制品 URL、落地页 URL / 海报源文件、全链路走查截图或录屏、平台建议走查记录。
**验收**：任意一名队员用自己手机从专属入口走到 fork，全程无人工帮助、无卡点。

## 附 A：每天固定动作（约 10 分钟，轮值同学负责）
