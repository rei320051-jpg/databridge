### 3.4 四个对比瞬间（高潮）
- **A 正常取数**：问"2026年9月各地区的净销售额环比对比"。
  - KPI：9 月净销 **17,198,835.91 元**（接口返回整数分 1,719,883,591，除以 100 显示为元）；
  - 柱状图故事：**华南 ▼15.72% 最差，华中 ▲1.53% 是唯一正增长**；华东 −3.50%、华北 −2.50%、西南 −7.31%。
- **B 澄清**："9月的销售额是多少" → 选净销售额 → 返回 **17,198,835.91 元**，与 A 完全一致；
  两个候选口径当月相差 **2,215,508.08 元**（成功退款总额）。
- **C 拒答**：点"为什么华东地区9月净销售额下降了" → `insufficient_data / causal_reasoning_unsupported`。
  （可补一句："华南为什么跌，平台同样不编原因，只给可查的方向。"）
- **D Agent 回放**：运行示例运营 Agent 生成 9 月经营简报，自动找出**华南 −15.72%** 并标注口径/来源/限制。

### 3.5 结果依据
- 翻出真实后端 SQL：整数分、半开时间区间、退款侧先按 order_id 预聚合、地区取 orders 订单快照；
- 数据集版本 demo-v1.1 + query_id 可在 `GET /v1/query-records/{id}` 复查。

### 3.6 实验证据（正式库实测）
- **S1 直接 Text-to-SQL：37 题完成 0 题；S2 完整治理：37/37 全部完成（100%）**。
- S1 把 9 道本该拒答的题（因果归因、预测、写操作、派生指标）全部"自信作答"；7 道歧义题无一澄清。
- 可念的虚高实例：9 月净销售额 S1 报 **18,166,729.12 元**，真实值 **17,198,835.91 元**，
  虚高 **967,893.21 元（+5.63%）**——SQL 能跑、不报错，钱算错了近 97 万。
- 数值错误独立归因：未排除失败/取消订单 **18 题**、JOIN 一对多重复累计 **16 题**、退款按支付月归属 **13 题**。
- IS-001 正式库实测：跨月退款 **1,356 笔（44.28%）、金额占比 45.55%**；
  若按支付月归属，9 月华东数字会被**回溯改写 329,335.21 元（−4.82%）**——已结账月份会持续漂移。

## 6. 评委提问预案（正式库增量问题）

- **"为什么用两万条的库，不用八万五的？"** → 八万五是页面参考实现自带的演示数据；两万条是成员 1 按共同契约独立交付、锁定校验的正式库，页面/Agent/SQL 三方同数，演示必须用可信链路。两套口径一致、数字独立。
- **"15.72% 会不会是数据巧合？"** → 数字由固定种子生成器产出并 sha256 锁定，任何人重算同一版本得到同一结果；环比方法（上一自然月对齐、零基不除零）在契约里固定。
- **"44% 的跨月退款是怎么回事？"** → 合成数据按给定分布生成，比例本身不代表真实业务；要证明的是口径后果：按支付月归属会让历史月份漂移，9 月华东一个格子就差 32.9 万元。
- 其余公共问题（只读、安全、SQL 注入、5000 元不变量等）沿用保底版 §6，答案不变。
