# 数据结构与业务约定 v0.1

日期：2026-09-29。供成员1实现、成员2和成员3复核。

成员1已确认四条开发规则：接口金额为整数分、页面展示元；退款按成功完成时间统计；地区使用订单产生时的记录；新/老客户使用数据集固定标签。其余业务约定和团队查询协议仍待确认。

## 表关系和共用约定

`customers (1) → (N) orders (1) → (N) refunds`。

数据库采用 SQLite，建表文件为 schema.sql。首版每个数据库只装载一个完整数据集版本；新版本使用独立数据库，不将多个快照追加到同一套业务主键中。dataset_metadata 记录版本、模拟数据标识、时区和已知覆盖区间，各表记录同一版本。

金额统一保存为整数分，结果金额字段仍为整数分，展示层除以100显示元；禁止浮点金额参与累计。时间统一使用 Asia/Shanghai 本地时间，格式 YYYY-MM-DDTHH:MM:SS，精确到秒。接口日期首尾均包含，执行时换算为 `[起日00:00:00, 末日下一天00:00:00)`。

## customers：客户

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| customer_id | TEXT | 主键；保留前导零 |
| customer_type | TEXT | new / returning；数据集给定的固定业务标签 |
| created_at | TEXT | 客户建立时间 |
| dataset_version | TEXT | 引用数据集版本 |

首版“新客户/老客户”指固定标签，不表示查询期间首次购买；若需“当月新客”，另行定义指标和实现，不能直接混用。

## orders：订单

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| order_id | TEXT | 主键；一个订单一行 |
| customer_id | TEXT | 外键，必须存在于 customers |
| region | TEXT | 下单时业务地区快照：华东/华南/华北/西部 |
| ordered_at | TEXT | 下单时间 |
| paid_at | TEXT / NULL | 成功支付时间；未成功支付时必须为空 |
| payment_status | TEXT | paid / cancelled / failed |
| paid_amount_fen | INTEGER | 实付分，非负；未成功支付时为0 |
| dataset_version | TEXT | 引用数据集版本 |

零元成功订单允许计入支付订单数和支付人数。成功支付后发生退款，原订单仍保留 paid 和原实付金额，不从支付指标中扣除。

## refunds：退款

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| refund_id | TEXT | 主键；每次退款单独一行 |
| order_id | TEXT | 外键；同一订单允许多条退款 |
| requested_at | TEXT | 申请时间，不参与成功退款指标时间筛选 |
| refunded_at | TEXT / NULL | 成功完成时间；失败/处理中为空 |
| refund_status | TEXT | success / failed / pending |
| refund_amount_fen | INTEGER | 本次申请或成功退款金额，正整数分 |
| dataset_version | TEXT | 引用数据集版本 |

只累计 success；退款地区和客户类型继承原订单及其客户。跨月退款按退款完成月份计算，不按订单支付月份计算。

## 完整性与后续导入检查

SQL约束覆盖主键、外键、状态、金额符号、字段空值组合和部分时间顺序。SQLite TEXT 本身不验证日期格式，正式CSV导入器仍须严格解析日期。外键必须在每个连接开启。

跨表检查还包括：三表版本一致、客户创建不晚于下单、退款必须对应已支付订单、退款申请不早于支付、同订单累计成功退款不得超过实付。固定样例和通用CSV质量报告、事务导入均已实现，使用方法见data_import.md。

金额异常阈值没有业务依据，暂不武断设定；负数/类型错误作为错误，过大金额的警告阈值待团队配置。数据覆盖范围以显式元数据为准，不能仅根据最早/最晚交易推断完整性。

## 避免重复累计

支付指标从 orders 独立聚合；退款指标从 refunds 关联唯一原订单后独立聚合；净销售额再合并两边结果。不得将原始 orders 与一对多 refunds 直接连接后累计订单金额。分组结果必须保留只有退款、没有当期支付的地区。
