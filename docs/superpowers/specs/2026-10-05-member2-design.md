# 成员二补齐设计

基线：main `83c9f40`。任务来源为三人分工 §4；附件中的协作要求作为范围参考，不授权给其他成员发送消息。用户要求自主完成，常规设计选择直接推进。

现有成果：规则/模型双模式、五个基础指标、两轮澄清、正式库只读执行和本地经营简报均已实现。共享 v1.2 已有三项派生指标，成员二拒答清单和执行映射未跟上；非法日期会抛异常，日期区间只取第一天，模型响应结构缺少边界校验，示例脚本未通过 HTTP 调用平台。

方案比较：修改成员一执行器能提供单 SQL 聚合，但扩大协作范围；只放开同义词会因执行器未支持而报错；选择在 Agent 层组合现有可信基础查询。固定共享字段和只读执行器保持兼容，后续成员一可实现原生比率执行。

派生查询必须同源、同期、同筛选、同分组，先聚合再相除，分母为零返回 null 和警告；金额分量以元输出。比率环比基于两个期间的比率，不能平均地区比率。返回 metric_kind、components、逐行分量及两份可读取的查询记录。任一分量失败或数据库文件在计算中改变时不返回数字。

自然语言：保留固定 REFERENCE_DATE；支持完整日期区间、中文月份年份、相对日和季度、明确排名。未支持的同比或任意两期比较明确拒答，不静默忽略。澄清保留已知日期、排序和环比，至多两轮；泛化人均消费按 DM-004 澄清。

模型：保持现有 Responses 调用和 JSON 模式，使用版本化提示词与共享业务上下文；非法响应统一 model_output_invalid，网络/配置问题为 execution_failed，不偷偷回退成功。无真实模型凭证时只做协议测试，不声称模型实测。

示例 Agent：本地路径保留，新增 --api 参数调用真实 /agent/query；网络/协议失败返回可理解状态。简报数字仅来自可信接口，缺失增长率、截断或无结果时披露限制。

验收：正式库基础结果及已有开发题不回归；三比率独立 SQL 核对、过滤分组、零分母、环比、追溯失败；日期异常/区间、多轮澄清；模型畸形响应；真实 HTTP 成功和断网失败。只使用开发集，不打开保留题调试。通过测试后提交功能分支及 PR，主分支合并留给团队复核。
