## P4 · 产品定位与四道防线（1:20–1:40）

**版面**：一句话居中 + 下方四个带编号的防线条

> **数桥 = 业务字典 + 查询计划 + 歧义澄清 + 结果检查，把数字在到你手里之前管四道关。**

1. **统一口径**：8 个指标写进共享契约，页面/Agent/SQL 服务同一份定义
2. **先澄清**：命中歧义词必须问清楚，最多 2 轮，不猜

4. **有边界**：因果归因/预测/写操作/未定义指标——明确拒绝并说明缺什么

**演讲词（成员 3）**："接下来我和两位队友分别展开：Agent 怎么理解问题、数字怎么保证正确。"

## P14 · 真实大模型复测：换上 DeepSeek，67 个数字一个没变（8:45–9:13）

**版面**：上方一句大字结论；左栏"架构边界"流程，右栏实测数据卡

> **把自然语言理解层换成真实 DeepSeek，67 题结果与离线规则逐字段一致，0 编造、0 失败。**

左栏 · 模型只做一件事，不碰数据库
```
用户问题 → [真实 DeepSeek：问题 → 结构化槽位]   ← 模型到此为止
         → 业务字典 / 澄清 / 护栏 / 只读 SQL / 聚合（全部本地、可验证）
```

右栏 · 2026-10-06 正式库 demo-v1.1 实测

| 指标 | 结果 |
|---|---|
| 开发集 / 保留集 | **37/37 · 30/30** |
| 与规则模式响应信封 | **67/67 逐字段一致**（含全部数据行） |
| 无依据编造 / 终态失败 | **0 / 0**（正确澄清 16） |
| 真正调用模型 / 护栏前零调用 | 54 题 / **13 题** |
| 平均时延（p90 / 最大） | 0.93s（1.03s / 3.67s） |
| 全量 67 题实付成本 | **≈ ¥0.023**（工作日高峰上界 ¥0.046） |

- **13 道因果 / 预测 / 写操作 / 口径冲突题，本地护栏在模型调用之前就拦截**——问题不外发、零 token，既安全又省钱
- 1 题模型侧瞬时抖动，自动重试一次后结果一致，用户无感知、无错误收尾
- 模型事实：请求名 `deepseek-chat`，官方别名实际服务 **deepseek-flash（V4.1-Flash）**；规则/模型可一键切换

**演讲词（成员 2）**："我们没有让大模型直接写 SQL——它只做最擅长的语言理解，把问题转成结构化槽位；用哪个口径、查哪张表、怎么聚合、能不能答，全部由本地字典和护栏决定，模型全程接触不到数据库。换上真实 DeepSeek 重跑 67 题，数字和离线规则一个不差；危险问题还没发出去就被拦下，13 题零调用。**模型可以替换、信任不打折**，这就是我们敢把它接进真实业务的原因。成本也极低，67 题总共不到三分钱。"

**素材**：`tests/_LLM真实模型复测明细.csv`（67 行）；`docs/测试报告.md` §4.2；执行器 `tests/run_llm_testset.py`。

## P16 · 当前限制（如实说明）（9:33–9:48）

**版面**：简洁清单（主动讲限制是加分项）
- 数据为固定种子生成的**模拟业务数据**（2 万单，2026-01~09），不代表真实经营
- 真实模型仅验证了**单一供应商**（DeepSeek / deepseek-flash）与 67 道零售订单题；跨模型、跨行业题集、长周期稳定性与峰谷价格波动尚未测量（本次 67 题实付约 ¥0.023、平均 0.93s）
- 模型只做"问题→槽位"，**"LLM 直接生成 SQL"不在产品架构内**；S1 仍保留为确定性对照基线（见 P13）
- 比率指标在 Agent 层组合分量实现，执行层 `/v1/query` 仍只接受 5 个基础指标
- 首版 2 个维度（地区/客户类型）、5+3 指标；同比、预测、因果、复购率不做
- 尚未在另一台电脑做全新部署验证（功能冻结后补 F08 换机自检）

**演讲词（成员 3）**："按赛题要求，我们如实说明边界——报告里没有任何未经验证的效果数字，连大模型不到三分钱的成本和 0.9 秒时延都是实测出来的。"
